## New code (`oracle-api/src/lib/belarc/`)

- **`types.ts`** — `ParsedSpecs` / `ParsedSection` / `SpecField` / `VolatilityTier` + `NotABelarcReportError`. The `ParsedSpecs` JSON (schema `version: 1`) is what Phase B will store on `HardwareScan.parsedSpecs` and Phase C will diff — field keys are stable (`memory.slot0.serial`, `localStorage.drive0.serial`, …).
- **`sections.ts`** — declarative registry of the 21 recorded sections (canonical key, Belarc header text, default tier) + `normalizeHeader()` (strips footnote markers: "Memory c,d" → "Memory").
- **`parseBelarc.ts`** — the parser. Uses `node-html-parser` (new dep). 12 custom per-section extractors assign per-field tiers; remaining sections fall back to generic line/table extraction with the section default.
- **`__tests__/parseBelarc.test.ts`** — 20 vitest tests. **`__tests__/fixtures/carter.html`** — the real Belarc export copied from `C:\Program Files (x86)\Belarc\BelarcAdvisor\System\tmp\(Carter).html`.

## Structure findings (real export ≠ original plan)

- Headers are `<h2 class="reportSectionHeader">`, not divs; footnotes are `<sup>` tags
- One `.reportSection` div can contain **multiple** header+body pairs (Local/Network Storage Volumes share one) — parser pairs each `<h2>` with its sibling body
- Serials live in `<table>` cells (drives, RAM slots via text lines, licenses, users, volumes) — cell-level extraction, not text mashing
- Virus Protection is a **table** in the real export (caught by a failing test — extractor now handles both table and line forms)
- Report meta (`Computer Name`, `Profile Date`, `Advisor Version`) parsed from `.reportHeader`

## Tier decisions made while implementing

- USB-attached drives → **skip** (removable media churns; only internal drives hard-compare)
- Batteries (Main Circuit Board table) → **skip** (health % drifts every scan)
- Monitors → **soft** (pluggable peripheral), display *adapters* → **hard**
- Communications: MACs → **hard**; IPs/DHCP/status dropped entirely (never recorded)
- Asset Tag under System Model → **soft** (org can legitimately re-tag)

# Session 3 — Hardware Audit Phase C: Comparison Engine

Phase B committed (`b35b054`), then built Phase C.

## New module: `oracle-api/src/lib/belarc/compare.ts`

`compareSpecs(baseline, current): ComparisonResult` — pure function, diffs on the stable field keys from Phase A.

- Per-field statuses: `match` / `warning` (soft diff) / `mismatch` (hard diff) / `missing` (in baseline, gone from scan) / `added` (in scan, not in baseline)
- **Missing/added escalate by tier** — a vanished or unrecognized *hard* component (removed RAM stick, swapped-in drive) is a mismatch; soft ones are warnings
- Skip-tier fields never enter the comparison (free space, last logins, battery health)
- Result JSON (`version: 1`): `overallStatus` (worst across fields), `summary` counts, `fields[]` with baseline/current values — stored on `HardwareScan.comparisonResult`
- 12 unit tests in `compare.test.ts`, built on the real fixture with targeted mutations

## Route integration (`hardware-audit.ts`)

- `POST /scan` now loads the asset's baseline and stores `comparisonResult` + `overallStatus` at upload time
- **Dry-run with `assetId` returns the comparison too** — the uploader sees discrepancies before submitting
- `PUT /scans/:id/baseline` now **recomputes all pending scans** of the asset against the new baseline inside the same transaction (stale comparisons were silently wrong after a swap)
- Baseline's own `comparisonResult` cleared with `Prisma.DbNull`

## Upload page

- Dry-run preview now renders the comparison: overall line (🟢/🟡/🔴), flagged fields with baseline → current values, hard-tier dots in red, capped at 12 rows
- Post-submit message reflects the stored status ("flagged for review (mismatch)" etc.)
