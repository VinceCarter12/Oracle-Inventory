## Department Runtime 500 Repair

Browser requests to `/api/departments?includeArchived=true` were returning 500 because the database used by the running API was a separate Neon runtime database whose `Department` table had not yet received `archivedAt`. The Hardware Audit badge also showed a 500 in the browser report.

The runtime database was preflighted for trimmed, case-insensitive active Department-name duplicates; none were found. The reviewed migration was then applied there: `archivedAt`, `Department_archivedAt_idx`, and `Department_active_name_ci_key`. Read-only verification confirmed the column and both indexes. The exact `HardwareScan` count used by the badge route succeeded and returned zero pending mismatches. The canonical Supabase migration remains intentionally unapplied and is still required when the approved Supabase/company target is ready.
