## Phase 1 Computer Intake Recommendation

Added [[Planning/Phase-1-Computer-Intake-Spec]] as the implementation-ready candidate for the first build phase.

Recommended phase plan:

| Phase | Scope | Relative duration |
|---|---|---|
| 1 | Company computer/laptop Manual Mode, branch-required official intake, canonical asset tags, optional assignment, device profile, repeatable RAM/storage, source labels, and activity log | Longest |
| 2 | Belarc proposal hardening after commercial licensing: conflict queue, raw evidence policy, source retention, and baseline separation | Medium-long |
| 3 | Network interfaces, IP/VLAN/port records, and branch connectivity views | Medium-long |
| 4 | CCTV/NVR camera-channel mapping and location display | Medium |
| 5 | Server roles, firewall, domain/file server profiles, and ISP circuits | Medium |
| 6 | Tools/stock quantity mode and serialized equipment split | Short-medium |

The longest phase is Phase 1 because it establishes the database pattern, official/manual workflow, draft/review UX, branch and assignment behavior, component child records, audit evidence, and production safety gates that later inventory families reuse.

No app code, schema, database, provider configuration, deployment setting, or Belarc licensing decision was changed.

## Phase 2-7 Implementation-Ready Candidate Specs

After context gate, enterprise UX audit, architecture review, and human approval, added vault-only implementation-ready candidate specs for the remaining expansion phases:

- [[Planning/Phase-2-Belarc-Proposal-Hardening-Spec]]: production-disabled Belarc proposal hardening with licensing gate, raw evidence retention decision, safe allowlist, provenance, conflict review, redacted logs, and rollback.
- [[Planning/Phase-3-Network-Infrastructure-Spec]]: branch-scoped interfaces, IP observations/history, VLANs, switches, ports, topology, and branch connectivity.

- [[Planning/Phase-6-Tools-and-Stock-Spec]]: tagged Asset versus quantity-managed stock, stock locations, immutable movements, derived balances, low-stock behavior, and permissions.
- [[Planning/Phase-7-Cross-Phase-Release-and-Operations-Spec]]: additive migration order, feature flags, staging, pilot rollout, backup/restore, observability, rollback, audit evidence, security verification, and acceptance gates.

Updated [[Home]], [[Planning/Pages/_Overview]], [[Planning/PLAN]], and [[Context]] to link the specs and keep status ownership intact. All phase specs are planning candidates only; no app code, Prisma schema, Supabase, Vercel, environment variables, deployments, Excel import restoration, or git commit was performed.

Final architecture consistency review aligned the specs on `Asset` as the identity/lifecycle root, typed child records, `InventoryFieldProposal`, branch/object authorization, explicit `RecorderChannel` history, server-authoritative rollout controls, and immutable stock movements plus ledger/count reconciliation. Phase 2 remains production-disabled pending Belarc commercial rights and retention approval.
