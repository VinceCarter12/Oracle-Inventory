## Release Architecture Review - 2026-07-28

- The approved production shape remains SvelteKit on Vercel, Express on Render, and PostgreSQL on Neon; the current state supports staging preparation only, not production cutover.
- The review identified blocking release gaps: unreconciled provider/local commit SHAs, an unversioned Prisma database, reflective CORS, remaining direct relative frontend API calls, a fixed seed credential, missing durable branch/object authorization, and in-process scheduling.
- A staged API-boundary change was prepared in an isolated worktree: exact-origin CORS via `CORS_ALLOWED_ORIGINS`, `/ready` database check, and opt-in scheduler. It is deliberately **not committed or deployed** because this sandbox cannot write the shared Git worktree metadata, and provider/database environment changes must wait for the required stable staging origin and release candidate reconciliation.
- Validation: API TypeScript no-emit check passed. The full frontend check could not update the isolated worktree's generated `.svelte-kit` directory because of filesystem ownership restrictions; it remains required on a clean CI/owner checkout.
- Do not create live test users yet. First rotate/remove the seeded credential, establish a migration baseline and restore proof, decide branch authorization, then provision disposable accounts through the supported path and store their credentials only in an approved secret manager.
