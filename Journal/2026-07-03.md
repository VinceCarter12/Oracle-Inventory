## What we did today

Decided to skip OTP login for now. Focused on finishing the dashboard WIP and wiring the reports page end-to-end.

## Phase B1 — Dashboard WIP cleanup

The uncommitted `dashboard/+page.svelte` already had the full layout: 5 StatCards, `ChartBar` (6-month assignments/returns), `ChartDonut` (condition breakdown), Branch utilization table, Top Categories grid, Recent Activity table.

**Fixed two issues:**
- Fetch was wrapped in a single try/catch — a `403` on `/api/activity` (for users without `access_logs` permission) would blank the whole dashboard. Now fetches independently with `.catch(() => null)` and short-circuits the activity fetch if the user lacks the permission.
- `{#if can(...)} {#snippet action()}` was in the wrong order — snippet must wrap content, not be nested inside an `{#if}`. Moved the `{#if}` inside the snippet.

**New component files (already in the working tree, untracked):**
- `ChartBar.svelte` — SVG bar chart, two grouped bars per month, scales to container, legend
- `ChartDonut.svelte` — SVG donut, dynamic arcs from `segments[]`, center total, legend
- `SectionCard.svelte` — section wrapper, `title`, `subtitle`, optional `action` snippet, `flush` mode

## Phase B2 — Reports page wired

### Backend (`oracle-api/src/routes/reports.ts`)

`GET /api/reports/summary` now accepts query params:
- `branchId`, `categoryId` — scope all KPIs, category stats, and branch stats to that filter
- `from`, `to` (YYYY-MM-DD) — control the movements-by-month window (capped at 12 months; falls back to last 6 if not provided or invalid)

All changes type-check clean (`npx tsc --noEmit` — 0 errors).

### New utility (`oracle-sv/src/lib/utils/csv.ts`)

`toCsv(columns, rows)` + `downloadCsv(csv, filename)` — client-side, no deps. Handles quoting, comma-escaping, and adds a UTF-8 BOM for Excel compatibility.

### Reports index page (`/reports`)

- Filter bar now actually works: Apply/Reset both call `loadSummary()` which rebuilds query params and refetches `/api/reports/summary`
- Removed dead status filter select (no active/inactive dimension on summary aggregates)
- Removed "Schedule report" button (no backend)
- "Export all" / "Export as CSV" / "Download all" → downloads current asset snapshot as CSV via the `total-assets` report endpoint
- "Export as PDF" → `window.print()`
- Added 3 missing reports to the table that already had backend handlers: **Assets by Branch**, **Employee Ownership**, **Branch Utilization**

### Reports detail page (`/reports/[id]`)

- "Export CSV" exports currently *filtered* rows (chip filter + search applied), flattening `_asset` and `_employee` composite columns into plain fields
- "Export PDF" → `window.print()`
- Download card items converted from `<div>` to `<button>` elements with proper disabled state

## Session 2 — Dashboard: remaining 5 widgets (medium → hard)

All remaining items from [[Planning/Pages/Dashboard]] built in one pass.

### Backend (`oracle-api/src/routes/reports.ts`)

- **`/api/reports/summary` extended** with two new fields:
  - `deptStats` — active assignments grouped by `employee.department` → `{ name, assets, employees }` (assets reach departments through people, not directly)
  - `recentMovements` — last 8 MovementLog events of type assignment / transfer / return_approved / resignation / new_hire, with asset + employee names
- **New `GET /api/reports/condition-trend`** — last 6 months of condition-related events per month: `repairsSent` (repair_send), `repairsReturned` (repair_return), `disposals` (disposal). Honest event counts from MovementLog — no fake historical condition snapshots.
- **New `GET /api/reports/movement-frequency?limit=N`** — top N assets (max 20) ranked by MovementLog count via Prisma `groupBy`, joined with asset name/tag/category/branch + `lastMovedAt`.
- Both new routes registered before the `/:reportType` catch-all. `tsc --noEmit` clean.

### Frontend

- **New `ChartLine.svelte`** — multi-series SVG line chart (fixed viewBox, scales to container), takes `series[]` defs with key/label/color, renders lines + points + legend.
- **Dashboard page** — 4 new sections:
  1. **Utilization panel** — 4 metric tiles (overall %, avg per branch, top branch, underutilized <30% count) — computed client-side from existing `branchStats`, zero extra requests
  2. **By Department table** — employees + assets held per department
  3. **Condition Trend** — 3-series line chart (repair sent = warning, repaired = link, disposed = error)
  4. **Most Moved Assets** — top 10 bar list with tag/branch subtitles
  5. **Assignment History** — flush table of recent movement events with type badges
- All fetches remain independent (`.catch(() => null)`) — one failing endpoint can't blank the page.
